Use **Integrations** in the Nakama dashboard to connect channels, bridge workers, and external tool providers.

## Available sections

- [Telegram](/telegram): configure the bot token, pairing flow, allowed users, and bridge worker behavior
- [WhatsApp](/whatsapp): link a phone number, pair accounts, choose group mention behavior, and manage the WhatsApp bridge
- [Discord](/discord): save the bot token, invite the bot, pair users, and run the Discord worker
- [Slack](/slack): create the app from a manifest, save the bot and app tokens, pair members, and run the Slack worker
- [Composio](/composio): connect SaaS toolkits with per-user OAuth and assign them to profiles
- [MCP Servers](/mcp): connect external MCP servers and expose their tools to profiles
- [Error tracking](/error-tracking): send this instance's own crashes to your Sentry, GlitchTip, Bugsink, or Rustrak project
- **Coding agents**: choose Nakama provider passthrough (default) or harness login on this server — see [Coding agent](/coding-agent#provider-passthrough)

## Direct worker runs

Each channel connection belongs to one organization and one agent. The dashboard passes both when it starts a worker. A direct run must set them itself:

```bash
export NAKAMA_CHANNEL_ORG_ID="org_your_org"
export NAKAMA_CHANNEL_PROFILE_ID="your-profile"
bun run dev:telegram   # or dev:whatsapp, dev:discord, dev:slack
```

Save the connection in the same Nakama config directory first. A running worker keeps the token it loaded at startup, so restart it after rotating a credential. **Disconnect** removes the connection's credentials, pairings, and saved channel sessions.

## What lives in Integrations

The dashboard groups together deployment-level and organization-level configuration that is not tied to a single profile page.

Common examples:

- channel credentials such as Telegram, WhatsApp, and Discord tokens
- bridge worker controls and pairing codes
- Composio toolkit enablement and OAuth connection management
